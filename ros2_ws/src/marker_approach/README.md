# marker_approach — マーカー基準の最終アプローチ制御（#74 / 追M4 相当）

マーカー（AprilTag）が見えている状態から、**マーカー面の法線上・距離 standoff の点**まで
寄って正対する。指定すれば、そこから**その場で約90度旋回してマーカーを真横に入れる**
（対象物の横に着けて、機体側面のアームのカメラで撮影するため）。

**部屋を探索して対象を見つける動作は対象外。** カメラ視野は水平±46度、150mmタグで
実用3m以内なので原理的に無理。「見えている状態から寄る」ところだけを受け持つ。

## 中身

| ファイル | 役割 |
|---|---|
| `marker_approach/turn_drive_turn.py` | **制御則本体。ROSに依存しない。** 設計の理由と踏んだ罠は全部この docstring にある。**直すときはここを読む** |
| `marker_approach/approach_node.py` | ROSの配線（座標変換・安全・購読）だけ |
| `tools/sim_approach.py` | **実機もGazeboも使わずに制御則を検証する運動シミュレータ** |
| `launch/approach.launch.py` | 接近制御 + `cmd_vel_safety`。マーカー姿勢の供給元は含まない |

マーカー姿勢の供給元は環境ごとに違うので、このパッケージには入れていない。

- **Gazebo**: `apriltag_ros` + `docker/sim/tools/sim_tag_bridge.py`（`sim_up.sh` が一式を起動）
- **実機**: 検出ノードは未取り込み（#74 の実機側で追って入れる）

## 動作の並び

前進と旋回を**同時に出さない**。区間に分け、切り替わりに0.7秒の静止を挟む。

```
ゴールへ旋回 → 静止 → 直進 → 静止 → 正対へ旋回 → 静止 → 測り直し
                                                        ├ 未達なら1周目へ戻る（最大8周）
                                                        ├ 1周で30mm縮まらなければ打ち切り
                                                        └ 到達 → 真横へ旋回 → 完了
```

**横移動(vy)は一切使わない。** Go2は横移動が効かないどころか、混ぜると前進そのものが
止まる（実機実測: vy=0.15の実効率1.3%、vy=-0.056が乗るだけで前進停止。同じ条件で
vy=0にしたら1652mmを11秒で走り切った）。この事実が設計全体を決めている。
**Gazeboの歩容は `linear.y` を受け付けてしまうので、simで横移動を検証してはいけない。**

## 検証

```bash
# 実機・ROSとも不要。歩容の下限速度・指令遅れ・視野・姿勢の曖昧性を実測値で模擬する
python3 ros2_ws/src/marker_approach/tools/sim_approach.py
python3 ros2_ws/src/marker_approach/tools/sim_approach.py --final-heading right
python3 ros2_ws/src/marker_approach/tools/sim_approach.py --sweep   # 届く範囲の格子
```

3モードとも **27/30 合格**（不合格は「法線から-35度で届かない」既知の配置）。

Gazeboで通すのは `docker/sim/tools/sim_up.sh`（`docker/sim/README.md` 参照）。

## 主なパラメータ

| パラメータ | 既定 | 意味 |
|---|---|---|
| `standoff` | 0.65 m | マーカーからどれだけ手前に立つか。**150mmタグでは0.58mを切れない** |
| `pos_tolerance` | 0.06 m | 到達判定。**四足は一歩10〜20cm。30mmでは判定に入らない** |
| `ang_tolerance_deg` | 5.2 | 正対判定。**これより厳しくしても入れない**（旋回の分解能） |
| `use_normal` | true | ゴールを法線上に置く。false なら視線上＝マーカーの手前 |
| `final_heading` | marker | `right`/`left` で真横へ旋回する |
| `side_turn_angle_deg` | 90 | **「真横の定義」ではなく「引きずり補正込みの目標角」**（後述） |
| `yaw_source` | none | `imu`/`odometry`/`sportmodestate`。真横旋回に要る |
| `fov_budget_deg` | 25 | 旋回後にマーカーを残す方位。**カメラ位置で判定する** |
| `drive_bearing_limit_deg` | 33 | 直進中にこれを超えたら区間を切って向き直す |
| `min_translation_speed` | 0.15 | **Go2はこれ未満では脚が踏み出さない** |

視野の既定値は実機（水平±46度）向け。**Gazeboは±31度しかないので絞ること**（12/18度）。

## 忘れると事故る事実

- **視野の判定は base_link ではなくカメラ位置で行う。** カメラは前方327mm（実機）に
  あり、近距離ではカメラから見た方位のほうが大きい（機体0.9m・方位29度 → カメラ44度）
- **弦は折れ線に刻む。** ゴールはマーカーの正面ではなく法線上の点なので、向きを変えずに
  近づく間マーカーの方位は**単調に増える**。法線から30度ずれた位置から1本で走ると
  到達時44度になり、視野をほぼ使い切る
- **届く範囲は距離に依存する。** 2m以上からなら法線±40度、**1mからは±20度まで**
- **精度の天井は制御ではなくタグの姿勢の曖昧性。** 平面タグの姿勢は2解あり、視線と法線の
  なす角が12度を切ると2解が拮抗して法線が分からなくなる。残る横ずれは
  `standoff x sin12度` ≒ 135mm。**ロボットはこのずれを検知できない**（自己申告は数mm）
- **法線をロボット座標系のベクトルで保持しない。** 旋回でずれる。視線と法線のなす角
  alpha（相対量）で保持する
- **真横へ90度回すとマーカーは必ず視野から出る。** この区間だけ見失い判定を止める
  （`marker_optional()`。**前後の静止待ちも含める**。外すと静止に入った瞬間に落ちる）
- **「その場旋回」はその場ではない。** Gazebo実測で75度回る間に機体が116mm動く。
  standoff 0.65mではマーカー方位の約9度に相当する。**ばらつきではなく偏り**
  （3回で-9.4/-9.5/-8.5度）なので、`side_turn_angle_deg` から差し引けば消える
  （90→81で -0.5〜-2.9度）。**standoff を変えたら測り直すこと**（効きは距離に反比例）
- **目標角まで回す旋回は、惰性ぶん手前で指令を切る。** 正対旋回が `max(許容値, 惰性)` で
  切るのとは判定基準が違う（あちらはカメラが現在値を返し続ける）。間違えると着地誤差
  5〜7度、直して1.2度になった

## 実測（Gazebo、真値で3回。`docker/sim/tools/sim_report_pose.py`）

| | 実測の幅 |
|---|---|
| マーカーまでの距離 | 0.581〜0.612 m（目標0.65に対し -38〜-69mm） |
| マーカー法線からの横ずれ | 34〜54 mm |
| マーカーの見える方位 | -90.5〜-92.9度（右真横 -90度に対し 0.5〜2.9度） |

距離が一貫して手前で止まるのは、橋渡しの距離推定にある+10mmの固定オフセットと、
引きずりで近づくぶん。**最終的な位置合わせはアーム搭載カメラの担当**という前提で渡す。

実機では**視線接近モード（`use_normal:=false`）のみ成功済み**
（1.85m→0.65m、位置誤差18mm/27mm・方位-2.3度/-4.2度、2回）。
**法線モードは実機未検証**（前進が数秒で止まる別の問題で中断中）。
