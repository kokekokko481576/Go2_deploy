# 自己位置推定 頑健性評価手順(Issue #14、自M3)

`docs/計画/自己位置推定.md` §3.4(M3: 頑健性評価)で挙げた5項目について、GATE1
(#36)完了後に実施する評価シナリオ・手順を先に文書化する(Issue #14本文の依頼)。
本ドキュメントは**手順の整理**であり、各シナリオの実施・レポート化は別途行う
(作業計画.md 自M3の完了条件「評価レポート + 3D化要否の判断材料」はその実施結果)。

## 0. 共通の前提・道具

- 環境: Gazebo cafeワールド、フェーズB(自作EKF/AMCL、`go2_localization`)
- 起動: `ros2 launch ~/ros2_ws/launch/demo.launch.py use_localization:=true`
- **真値との比較**(Issue #43): `./docker/sim/tools/start_ground_truth.sh`で
  Gazebo物理演算の真値(`/gz_ground_truth/pose`、sim限定)を取得できる。本評価は
  「推定がどれだけ真値からズレるか」を見るのが目的なので、全シナリオで起動しておく
- 初期姿勢の再指定: `~/ros2_ws/src/go2_localization/scripts/set_initial_pose.sh x y yaw度`
  (`/go2_localization/initialpose`へpublish)
- 大域再位置推定: `~/ros2_ws/src/go2_localization/scripts/relocalize_global.sh`
  (`/reinitialize_global_localization`サービス。パーティクルを地図全体へ再散布)
- 現在の推定 vs 真値の比較:
  ```bash
  # 推定(map->base_link)
  ros2 run tf2_ros tf2_echo map base_link --ros-args -r /tf:=/go2_localization/tf
  # 真値
  docker exec go2-sim bash -c "source /opt/ros/jazzy/setup.bash && \
    ros2 topic echo /gz_ground_truth/pose --once --no-daemon"
  ```
- 指標・許容誤差はGATE1(#36)と揃える: xy 0.25m / yaw 0.2rad(≈11.46°)を「実用上の収束」
  の目安にする(それ以上ズレたら「未収束」とみなす)

## 1. 初期位置1m/30°ずれからの収束

**目的**: 初期姿勢の仮定が実際の位置と1m・30°ずれた状態から、AMCLがどれだけの時間・
移動距離で収束するか。

**手順**:
1. ロボットを原点(0,0,0)付近に置いたまま、`set_initial_pose.sh 1.0 0.5 30`のように
   実際の位置から1m・30°ずらした値を`initialpose`へpublish
2. `send_goal.sh`で適当な距離(2〜3m)のゴールを投入し、通常通り走らせる
3. 推定(`map->base_link`)と真値を1Hz程度でログし、誤差(xy, yaw)が許容誤差以内に
   収まった時点を「収束」と判定する

**観測項目**: 収束までの時間・移動距離、収束するまでの誤差の推移(単調に減るか、
振動するか)、収束後に再発散しないか

**判定基準**: ゴール到達(またはある程度の走行)までにxy 0.25m/yaw 11.46°以内へ収束すること

## 2. 一様通路でのドリフト

**目的**: 特徴の乏しい(壁が単調に続く)区間で、スキャンマッチングの手掛かりが少ない
状況でのドリフト量。

**手順**:
1. cafeワールド内で、家具や角が少ない一様な壁沿いの区間を選ぶ(地図を見て選定)
2. その区間を往復するゴール列を送り、走行中の推定・真値のズレを記録
3. 開けた/入り組んだ区間との比較用に、同じ距離を家具の多い区間でも走らせて対照とする

**観測項目**: 単位距離あたりのドリフト量(m/m)、単調に増えるか収束するか

**判定基準**: 定量的な合否基準は無し(#10のドリフト率計測と組み合わせて特徴付ける)。
一様区間でドリフト率が有意に悪化するかどうかを見る

## 3. 対称環境での誤収束

**目的**: 形状が対称・反復する環境で、AMCLが正しい仮説ではなく鏡像/別の対称候補に
収束してしまわないか。

**既知の知見**(#27対応中、2026-07-17に観測): `relocalize_global.sh`で大域再位置推定を
実行後、動き回らせながら収束を観察したところ、真値から2m付近まで寄った後に
**対称な別仮説へ十数m飛ぶ**挙動を確認済み(詳細: `go2_localization/README.md`
「初期姿勢がズレたときの復旧」、Issue #14既存コメント参照)。評価時は適応リカバリ
(`recovery_alpha_slow: 0.001` / `recovery_alpha_fast: 0.1`、#27で有効化済み)が効いた
状態で行う。

**手順**:
1. cafeワールドの対称/反復区間(同型の配置が並ぶ場所)を確認
2. `relocalize_global.sh`で大域再位置推定を実行
3. その区間内を歩かせ、真値との誤差が発散(対称候補へジャンプ)しないかを記録
4. 発散した場合、どのくらいの頻度・条件(移動距離、往復方向)で起きるかを記録

**判定基準**: 定量的な合否基準は無し(既知の弱点として頻度・条件を特徴付けるのが目的)。
必要なら3D化(点群マッチング)や特徴追加で対称性を解消する判断材料にする

## 4. 遮蔽時の劣化

**目的**: 人や障害物が顎LiDARの視野の一部を遮ったときの推定劣化。

**手順**:
1. 走行中にcafeワールド内の可動物体(テーブル等)、または新たに小さな障害物を
   ロボット近くに一時的に配置し、視野の一部を遮る状況を作る
   (Gazebo GUIでモデルを手動配置するか、`gz service`でスポーン)
2. 遮蔽の有無での推定誤差・共分散(`/go2_localization/amcl_pose`のcovariance)の
   変化を比較する

**観測項目**: 遮蔽中の誤差増加量、遮蔽解除後の復帰時間、共分散の増減
(経路追従側の減速判断への使用可否)

**判定基準**: 定量的な合否基準は無し。遮蔽の程度と誤差増加の対応関係を特徴付ける

## 5. 鋼板マルチパス異常値の頻度

**目的**: 鋼板反射によるLiDAR異常値(マルチパス)の頻度。距離・強度フィルタの
必要性を判断する。

**制限(重要)**: **cafeワールドには鋼板/金属反射面が無く、現状のsim環境では検証できない**。
この項目は実機または鋼板を含む模擬環境(model追加や実船区画)が無いと評価不能。
sim側で代替するなら、Gazeboで高反射率マテリアルを持つ壁モデルを追加する案があるが、
LiDARプラグインの反射モデルがどこまで物理的に正しいマルチパスを再現するかは未検証。
実機接続(#3)が進んだ段階で優先的に評価する

## 6. 接触時のオドメトリオーバーシュート(新規、2026-08-04追加)

**背景**: 元は#26で「壁接触時に脚オドメトリが滑りを検知できずAMCLが補正しきれない」
可能性が指摘され、本issueで追跡することになっていた。#23の実装確認中(2026-08-04)に、
Gazebo真値との比較で実際に確認: 障害物接触1回あたり位置に0.2〜1.0m程度のズレが残る
(詳細: 本issueの2026-08-04コメント、PR #48/#51/#52)。#43(Gazebo真値ツール)により
定量評価が可能になったため、正式な評価シナリオに追加する。

**手順**:
1. `docker/sim/tools/start_ground_truth.sh`で真値を起動
2. 家具や壁にぶつかりやすいゴール(cafeワールドの家具配置を踏まえて選定)を送る
3. 接触発生時刻の前後で、推定・真値それぞれの位置変化量を記録
4. 接触1回あたりの真値との誤差増加量(m)を複数回サンプルし分布を取る

**観測項目**: 接触1回あたりの誤差増加量の分布、リカバリ(#23/#50のBTリカバリ)後に
誤差が収束し直すまでの時間、GATE1(#36)の到達成功率への影響度

**判定基準**: 定量的な合否基準は無し(現状すでに0.2〜1.0mのズレが確認済みなので、
低減策(#14本体課題、#49のトルクベース検知など)の効果測定の基準値として使う)

## まとめ・3D化要否の判断材料への使い方

各シナリオの結果は、`docs/計画/自己位置推定.md`が想定する「2D AMCLで足りるか、
3D化(点群マッチング)が必要か」の判断材料になる。特に:

- シナリオ3(対称環境)・シナリオ5(鋼板マルチパス)は、2D特徴の乏しさに起因するため、
  ここで有意な問題が確認されれば3D化の優先度が上がる
- シナリオ1・2・6は主にオドメトリ・EKF側の特性(3D化とは別軸)なので、2D/3Dの
  判断には直接影響しない
